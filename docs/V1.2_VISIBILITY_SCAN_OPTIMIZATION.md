## Implementation

The merged iterator now considers newer files first for equal IDs. It selects
an eligible winner before skipping any dominated version. A higher record
version in an older file still receives the full visibility check; an invisible
newer version cannot hide an older committed row. Every physical row still polls
cancellation. One encoded winner buffer is reused throughout the scan.

Document and selective encoded-row paths share the same field-based visibility
rules, eliminating temporary projected JSON metadata maps. Field precedence,
legacy disabled-Raft behavior, commit-index/floor checks and per-row Raft role
checks remain intact. No cached leadership bypass, reduced scan coverage,
durability change, storage migration or new authoritative store is introduced.
The tests cover higher-version older files, pending overlays, block-boundary
version runs, ties/tombstones/cancellation and an independent 18-row visibility
matrix in both memtables and SSTs under legacy and enabled-Raft modes.

A read-only mechanism diagnostic scanned approximately two million physical
rows in the restored fixture. Projecting six metadata fields took about4.65s;
looking up the two used fields directly took about3.4s. It isolated avoidable
projection work, not end-to-end query latency or a new visibility policy.
