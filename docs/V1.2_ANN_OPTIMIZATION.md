Authorized work, in order:
1. Add per-query stage timings, then profile source-definition capture, graph
   traversal, authoritative record resolution, scoring and final validation.
2. Reduce record materialization through a memory-accounted, generation-bound
   packed-record cache. A cache is derived; shared WAL/LSM stays authoritative.
   Every cached result must preserve tenant and visibility checks and the final
   source certificate. Cache updates/deletes and invalidation must be exercised.
3. Normalize derived cosine vectors once, use bounded compact traversal scratch,
   improve neighbor selection, and stage privately with reusable build scratch.
   The initial implementation retains one builder per index; it adds no parallel
   construction workers. Build speed is measured before adding more concurrency.
   Never silently convert authoritative float64 records or change exact scoring.
4. Persist checksummed derived graph checkpoints; validate identity/configuration
   and current committed source before reuse. Partial/corrupt/stale files must
   rebuild or report explicit unavailability, never establish record durability.

The checkpoint format must remain separate from WAL/SST/replication formats and
must not turn index files into an authoritative store. No graph construction or
checkpoint I/O executes in the Raft acknowledgement path. All memory, workers,
file sizes, cancellation and shutdown remain bounded.

Verification: targeted numerical/recall tests, tenant/update/delete/concurrency
regressions, memory exhaustion, corruption/publication crashes, restored-source
mismatch and restart. Then full native/Community/failpoint gates and a fresh
three-system benchmark with the same data, resource/ACK/recall targets. Preserve
failed attempts. Beating pgvector is a target, not a passing-test assumption.

Implemented behavior under qualification:
- HNSW-only native generations cache losslessly compressed MessagePack records.
  Graph payloads, vectors, links and traversal scratch share the existing byte
  budget. Candidate copies are bounded by the request result-byte ceiling;
  decoded cache records are individually capped at 16 MiB. Large payloads may
  require more index memory or produce an explicit build/resource error.
- Queries rank candidates from selectively decoded original numeric values,
  materialize only the selected top K, enforce tenant/read visibility, and
  revalidate the committed source certificate. Historical/snapshot contexts and
  unsupported filters continue through the existing explicit exact policy.
- Metadata-only maintenance replaces the cached record even when its normalized
  vector does not change. Deletes remain non-result navigation tombstones.
- Only derived cosine vectors are normalized once. SSE2 uses double accumulation
  on x64; other platforms retain a scalar fallback. Authoritative float64 JSON
  and exact scoring are preserved. Links use 32-bit ordinals with a checked
  capacity bound. Bulk construction stages records directly in the graph budget
  and reuses a bitmap, clearing touched words between traversals.
- Graph-only full builds write a private, checksummed topology cache beside
  DATA_ROOT (`<DATA_ROOT>.vector-derived-v1`). A current committed source scan,
  sorted full-record/vector SHA-256 fingerprint and configuration/namespace
  binding are required before reuse. Process-local freshness counters are never
  trusted across restart. Topology contains tombstoned navigation vectors but
  does not make records durable. Backups of authoritative data require no cache.
- Files are atomically replaced and flushed; interrupted temporary files are
  ignored/cleaned. Individual files respect the index byte limit; this system
  cache has a 2 GiB directory ceiling and bounded retained file count. Optional
  checkpoint failures are visible as `checkpoint_error`; fresh in-memory search
  can still work. This is a system cache budget, not a new tenant billing quota.
- Checkpoints currently cover completed full builds. Incremental edits can make
  the saved source fingerprint stale: restart then rebuilds safely. This change
  does not claim incremental checkpoint persistence, automatic startup loading,
  persistent hybrid/flat indexes, clustered qualification or production readiness.
- `payload_fetches` counts candidate resolutions for compatibility;
  `generation_record_hits`, `authoritative_fetches` and
  `document_materializations` distinguish actual cache/storage/materialization
  work. `timings_ms` separates definition/preparation, graph, record resolution,
  scoring and final validation/finishing; total also includes ranking and
  materialization. Client timing additionally includes RPC/serialization/transport.

Precision follow-up: packed-record reranking uses a dedicated wide-accumulator
MessagePack scorer, matching the previous `vectors::score` behavior, including
near-zero vectors. The existing packed exact scorer keeps its double-accumulator
behavior through the same parser. Tests compare all three metrics exactly with
the historical reference for zero, tiny, ordinary and very large finite values.
The shared parser change requires the existing storage/exact regression gates.

Concurrency boundary: initial construction/restoration is private and publication
retains shared ownership. Incremental maintenance still mutates the graph and
cached records under its per-index shared mutex, then advances the generation
certificate. Queries retain their generation and copy candidate records while
holding graph read access; they must validate the current committed certificate
before returning. This is not an implementation of immutable incremental graph
snapshots. Snapshot/bounded read contexts remain ineligible for this ANN path.

The host shut down during the final rebuild on 2026-11-03. That attempt's logs
remain incomplete; no new benchmark numbers were produced. The resumed
production build completed successfully. Qualification and benchmark controllers
are now supervised user services with explicit exit receipts; they reuse saved
build objects and preserve earlier diagnostic evidence.

Each engine verified 45 surviving acknowledged mutations, five deletions,
count 999,995 and sampled post-recovery Recall@10 0.99. Qdrant's measured
post-restart index readiness wait was 4.51 s; no zero rebuild time is invented.
The packed exact index required 9.87 s preparation on PacificDB. Filtering uses
an exact fallback without dedicated metadata indexes on any comparator.
Local loopback connections use disabled/trusted authentication and no TLS;
authenticated SDK functionality was tested separately. Fixed system order,
dynamic CPU clocks, active background applications and different native
protocols remain limitations. Do not generalize this 25D standalone trial to
high-dimensional embeddings, RF3, shard completeness or secured deployments.

Historical PacificDB ANN p50 was 19.83 ms; this run measured 2.195 ms (about
9.0 times lower). Initial build fell from 2,040.66 s to 952.31 s. Whole-lifecycle
peak PSS increased from 2,340.75 to 2,784.50 MiB and a 408.21 MiB derived cache
was added. These are observed separate-run differences; old power/frequency
conditions were not frozen, and selected efSearch changed from 200 to 100.
They must not be represented as a controlled code-only speedup.

The candidate is about 11.6% slower than pgvector in serial ANN p50, with lower
achieved recall. Its four-client static QPS is higher in this trial, also at
lower recall. Neither observation establishes an overall database win.
Ingestion, filtering, write ACK latency, memory and dirty recovery remain
material performance limitations.

## Checkpoint reuse and operational limits

The main crash occurs after mutations, so its saved topology is stale and was
correctly rejected. The measured rebuild publishes a new full-build checkpoint.
A separate subsequent **clean** restart of the unchanged 1M fixture passed:
startup 0.912 s; committed-source validation plus topology import 34.724 s;
`checkpoint_restored=true`; count 999,995; all 45 surviving mutations and five
deletions verified; ten independent-reference queries with Recall@10 0.99.
Its raw result, source and exit receipt are bundled under `qualification/`.
These timings are separate from the comparative benchmark and do not replace
its dirty-restart result. The earlier 100K unchanged-source SIGKILL reuse also
passed. No claim of instant startup loading or incremental checkpoint persistence
is made.
