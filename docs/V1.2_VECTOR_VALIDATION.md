## Implementation report

The [architecture/gap assessment and target/file-level plan](V1.2_VECTOR_ARCHITECTURE.md)
preceded the implementation. This checkpoint changes exact ranking and vector
visibility, not authoritative storage or consensus. Implemented:

- `vector_top_k.hpp`: bounded worst-first heap; deterministic score/ID ties;
  lazy competitive-candidate materialization; retained serialized-document budget.
- `database_engine.cpp::queryVector`: exact selection, bounded ranking, explicit
  scan/cancellation/output-limit failures; tenant/read visibility checks on both
  paths; direct numeric-array scoring without an extra decoded vector allocation
  and with the query norm computed once. Legacy non-numeric decoder fallback remains.
- `server.cpp`: vector read-context scope/cleanup using existing consistency
  aliases; existing strong Raft barrier retained.
- Node wrapper: additive `searchMode` mapping and validation; existing omitted
  option leaves the original wire request unchanged.
- A subsequent selective-decoding checkpoint adds `MsgpackRowView::project` and
  `LSM::LatestRowView::project`. Only exact vector search calls the new API; it
  decodes selected metadata/vector fields in one pass instead of rescanning the
  packed row per field. Existing document/media call sites and encoded bytes are
  unchanged. Projection tests cover null/missing fields, nested values, Unicode,
  map16 encoding, duplicate selection names and malformed/trailing input.
- Exact scanning enforces the existing query time budget even on a connection
  worker without a cancellation token; a zero-budget regression exercises rejection.
- Independent-reference tests, concurrent payload/score consistency test,
  expanded vector restart/backup/RF3 coverage, and reproducible diagnostic tools.

Existing mutation, WAL, SST format, Raft apply, media and document implementations
are unchanged. This reduces integration scope; it does not prove every existing
flow correct under all workloads.

## Compatibility and risk report

Document/media regression suites and the exercised RF3/restore paths passed.
Legacy arrays remain unchanged; there is no data migration or new WAL/Raft protocol.
The candidate also read and ranked the million-row dataset written by the original
released 1.1.2 benchmark engine, validating counts and returned payloads/scores.
Full document results and score conventions remain. Exact limit exhaustion is now
an explicit error rather than a successful partial ranking; callers must handle it.
Node's new option is additive; Python/Java existing raw options remain usable.

Remaining risks:

- Historical checkpoint risk, resolved by checkpoint 1: the quadratic legacy ANN
  builder, signature scans, graph copies and global graph lock were removed.
  Public ANN now reports unavailability unless safe exact fallback is permitted.
- Exact candidate retention is bounded; shared iterator memory/locks, allocations
  and result-size estimates are not hard process-wide resource reservations.
- General historical MVCC iteration and collection-generation capture need a
  separate storage/visibility design; do not promise historical vector snapshots.
- Historical checkpoint risk, resolved by checkpoint 1: global QueryLimiter
  truncation flags were replaced by request-owned state with queued-worker,
  keepalive-RPC and tenant concurrency coverage, including ThreadSanitizer.
- No durable vector schema/float32 migration, sparse/named vectors, asynchronous
  freshness contract, distributed coordinator or advanced compression is implemented.
- An uncommitted development build has no release artifact/upgrade certification.

## Native service and hybrid development checkpoint (2026-10-30)

The trusted C++ integration now has a bounded shared index registry, source-memory
reservations, cancellation/deadlines, authoritative candidate revalidation and
composite vector/lexical generation publication. A real derived BM25 inverted index
and ranked RRF hybrid retrieval are implemented and tested internally. Existing
public query modes remain safely gated; these additions are not public production
ANN or distributed retrieval qualification.

Mixed document/media/vector traffic exposed two secondary-index defects: rebuild
lock inversion and delayed queued payloads resurrecting deleted entries. Rebuild and
batch maintenance now use collection-before-index locking; pending IDs resolve the
latest authoritative versions before application. Same-collection writes may wait
through a rebuild; indexed batch maintenance adds point-read I/O. WAL durability and
formats are preserved. Normal and ThreadSanitizer mixed tests pass, and the current
normal CTest suite passes 33/33. The broader post-repair checkpoint passed 62 top-level checks.

See the [implementation, test evidence and qualification boundaries](V1.2_NATIVE_SERVICE_AND_HYBRID.md)
for actual scope, raw failures and scale diagnostics. The release remains INCOMPLETE.

The trusted native C++ service subsequently completed 1M durable vectors, 25D
cosine, M=16/ef_construction=200/ef_search=300, 100 held-out queries: Recall@10
0.991, query p50 56.202 ms, source/build 2165.29 s, peak RSS 1,415,780 KiB.
WAL/fsync/flush-on-commit remained enabled (2,001 physical syncs). These are
concurrent-work diagnostic timings, not a controlled before/after comparison or
p95/p99/public/distributed readiness evidence. See the native service report.
