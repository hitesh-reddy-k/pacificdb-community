## A. Implementation

`vector_memory_budget.hpp` provides atomic allocation accounting and a C++17
polymorphic memory resource. Each graph has a local allocation-byte limit; an
optional shared budget limits multiple graphs/generations together. Reservations
fail before upstream allocation and roll back if either the shared reservation or
upstream allocation fails. Deallocation releases both counters. There is no global
allocation mutex or replacement process allocator.

`read_cache.hpp` / `hnsw_index.cpp` now place graph node storage, IDs, vectors,
neighbor layers, ID-map entries/buckets, construction worklists and internal query
heaps/visited maps in that resource. Reallocation counts old and new allocations
while both are live. Default local limit: 256 MiB, configurable through
`HNSWConfig::maxMemoryBytes`. Statistics expose current/peak charged allocation
bytes, configured limit and graph health.

Mutation allocation failure may leave an unpublished graph partially edited. The
instance becomes unhealthy and rejects subsequent searches/inserts rather than
serving it as a valid index. Read-side scratch exhaustion does not mutate or poison
the graph. Limit failures report `vector_index_memory_budget_exceeded`; ordinary
upstream allocation failures remain distinct exceptions.

`vector_index_generation.hpp/.cpp` accept a shared graph budget and give each
generation ownership of its accounting resource. Reader-retained old generations
continue consuming shared quota after manager destruction or publication. Failed
construction is FAILED, never READY; old data remains authoritative in WAL/LSM.

The internal catalog accepts `max_index_bytes` (1 KiB–1 GiB, default 256 MiB) and
maps it to graph configuration. Historical definitions missing that optional field
receive the default. This is derived-index configuration, not a vector storage
precision migration or collection write-validation schema.

## C. Boundaries and remaining work

This caps **requested allocation bytes inside the graph and internal scratch**,
not whole-process RSS. Allocator overhead, caller-owned query vectors/results,
source producer allocations, collected source buffers, JSON/document materialization
and storage iterator memory are outside this resource. Source collection retains
its separate existing source-byte policy. A host must supply shared admission;
the default standalone graph limit alone is not database-wide or tenant-wide
quota integration.

A bounded database-wide worker/registry service, source admission, tenant quotas,
per-traversal cancellation/deadlines, incremental committed maintenance and public
lifecycle routing remain INCOMPLETE. This resource implementation does not qualify
those missing layers or enable the graph through public query routing.
