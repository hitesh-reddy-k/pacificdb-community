# PacificDB Community v1.0.1

This source update makes the first run clearer and applies the project →
database → collection flow to the native shell, npm shell, and Node.js client
creation helpers.

## Added

- The Node.js client now has `createProject(name)`, `useProject(id)`, and
  `useDatabase(name)` helpers. Creating a project selects it; creating a
  database maps it to that project and selects the database.
- A website release page and a shorter README Quick Start explain the required
  creation order with one working example.

## Removed

- The native and npm interactive shells no longer offer `login`, `whoami`, or
  `logout` commands. Shell help and documentation no longer advertise them.
- The shells no longer load or save session tokens in CLI context. An older
  saved token is removed when the shell opens.

Engine authentication and the Node.js client's authentication API remain
available for deployments that use them. API key commands also remain in the
shell.

## Improved

- Both interactive shells require a selected project before creating, listing,
  selecting, or dropping a database. They require a selected database before
  creating a collection.
- Schema creation checks the current project and database mapping, so a stale
  saved context cannot create a database for a deleted project or a collection
  in a database no longer mapped to that project.
- Node.js `createDatabase` and `createCollection` validate the same order and
  project mapping. Existing applications that call these helpers must select a
  project first. Raw protocol requests and other SDKs still use the engine's
  existing API.
- The README, website examples, and shell reference now describe the same
  v1.0.1 workflow. The stale beta badge on the website is gone.

## Try the source update

Build from this checkout, run `pacificdb`, then enter:

```text
create project demo
use project project_...
create database app
use app
create collection users
insert users {"id":"1","name":"Ada"}
find users {"id":"1"}
```

Replace `project_...` with the ID returned by `create project`.

## Availability

The source and package manifests are versioned `1.0.1`. The website's
installer links still point to the published `1.0.0` artifacts, and npm
`latest` remains `1.0.0` until 1.0.1 packages are published. Do not treat the
source version or this note as evidence that new installers have been released.

The local restart matrix currently fails a durability assertion: an updated
document reads correctly before a graceful restart but returns its earlier
value afterward. This is under investigation; 1.0.1 is a developer-testing
source update, not a qualified package release.

The [release evidence contract](../RELEASE_EVIDENCE.md) and
[compatibility policy](../COMPATIBILITY.md) describe the qualification needed
before a packaged release.
