## A. Implemented and exercised

`MsgpackRowView` now supports an optional immutable root-field index with at most
32 borrowed field spans per cursor. The vector `LSM::visitLatest` path opts in.
Wider objects fall back to the original field lookup for uncached names. Ordinary
storage readers retain the existing default. This adds approximately 1 KiB of
bounded cursor-local state; it does not retain collection-sized query data or
introduce mutable process-global query caches.

A raw dense score kernel reads MessagePack numeric arrays directly, preserving
stored float64 values and signed/unsigned integer conversion semantics. Cosine,
negative Euclidean and dot scores use the same accumulation order and zero-norm
threshold as the prior array kernel. Unsupported representations, named/sparse
vectors and legacy numeric strings use the existing decoder. Authorization,
tenant/visibility predicates, filtering, bounded top-K, deadlines and explicit
resource errors remain in front of result return. Only top-K candidates are fully
materialized. There is no authoritative data migration, new WAL, changed fsync
policy or persistent-format conversion.

The exact-reader audit also found and reproduced a correctness defect: an older
replayed memtable value could override a newer SST version, and an older live row
could resurrect an SST tombstone. SST iteration now exposes tombstones to this
specific merge, compares versions across layers, and preserves memory-last tie
resolution. The retained red fixture failed at `replayRows.size() == 1`; the fixed
fixture passes normally and under ThreadSanitizer.

## C. Performance evidence

Original GloVe-25 corpus: 1M vectors, cosine top-10, same ten held-out queries
(indices 100–109), three repetitions, two warmups per mode. Corrected PostgreSQL
adapter disables automatic statement preparation and retains executed HNSW plans.
Both products return vector payloads and scores. Scratch copies are on tmpfs;
background applications, clock/thermal variation and small repeated query sets
limit generalization. No ingestion/build or p95/p99 claim follows.

| --- | ---: | ---: | ---: | ---: |
| PacificDB public exact | 4298.35 | 4503.43 | 4637.84 | 4503.43 |
| PostgreSQL exact | 83.59 | 82.36 | 76.88 | 82.36 |
| pgvector HNSW | 1.848 | 1.902 | 1.985 | 1.902 |

Both exact paths matched independent ground truth. pgvector ANN is an approximate
reference, not a completed public ANN comparison. Public PacificDB ANN stays gated.
The prior checkpoint's PacificDB median was 7556.13 ms. The new measurement is
about 40.4% lower (1.68x), but these are different-time workstation measurements,
not a controlled randomized before/after trial. **PostgreSQL exact is still 54.7x
faster in the fresh replay. The competitive performance goal remains INCOMPLETE.**

Decoder microprofiles are separate from the database benchmark. The initial field
index alone did not improve projection (1.35 s baseline versus 1.44 s indexed for
300K synthetic rows). Adding raw numeric scoring reduced that component; final
sequential diagnostic results are retained in `decode-*-final.json`. They must not
be presented as client-observed database latency or a complete CPU profile.

## D. Next implementation and qualification gates

`FlatVectorIndex` is a new dense float64 derived-component development step. It
packs numeric values, cached norms and IDs, charges allocations and search scratch
to existing vector budgets, freezes before search, rejects failed builds, bounds
heap retention and uses deterministic score/ID ordering. Its independent reference,
precision, memory-failure, cancellation and concurrency tests pass normally;
sanitizer and generation integration are separate pending gates. It is not yet
connected to authoritative-source certificates, public routing, or storage/Raft
mutations and must not be represented as an engine performance result.

Planned integration reuses the existing generation manager and durable catalog;
it must preserve source float64 precision, full eligible-row coverage, tenant/read
visibility, mutation invalidation, bounded staging, retained-generation accounting
and authoritative payload revalidation. No independent durable vector store is
permitted. Unsupported filters/contexts must use the existing complete exact path
or an explicit resource/freshness error.

The new trusted `native_vector_glove_qualification` tool copies a stopped snapshot
under its shared root lock into an owned disposable root, rejects symlinks, rebuilds
from committed data and records held-out ANN hits. The frozen 1M GloVe run subsequently completed: Recall@10 0.986, p50 19.75 ms,
source/build 1685.18 s, for its recorded internal binary/configuration. See
`v1.2-evidence/packed-vector-execution/glove-native-summary.json`. Synthetic
random-vector recall alone cannot qualify GloVe recall.
No public ANN rollout follows until the relevant source/lifecycle/resource and
recovery gates pass. Its C++ internal timings are not an equivalent public TCP API
comparison against pgvector.

Public ANN/hybrid lifecycle, incremental maintenance, enforced collection schemas,
distributed record transfer/search completeness, advanced disk/quantized indexes
and full production upgrade/security/recovery qualification remain INCOMPLETE.
