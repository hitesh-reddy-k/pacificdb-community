# ANN commit visibility follow-up (unreleased)

This change removes unnecessary incremental ANN invalidation when unrelated
documents or media advance the global Raft commit index. It does not increase
the default freshness wait, enable exact fallback, or change authoritative data,
WAL acknowledgements, storage format, replication format, or SDK requests.

## Failure and scope

The earlier 1M-vector mixed run stopped after approximately 19 minutes with three
strict ANN errors while the host was under memory pressure. Its failed evidence
is retained. A later 30-minute run on the previous binary passed, including
recovery; that successful run did not establish resolution of the pressure case.

A smaller regression now reproduces an unnecessary `STALE` error on that previous
binary after an unrelated document commit, with Raft fully applied. The public
regression deliberately sets `index_wait_ms=0` to expose unnecessary maintenance.
A separate fault test pauses final query validation for 1,100 ms, beyond the
unchanged default 1,000 ms freshness retry budget, while an unrelated document or
an actual vector is changed. These are controlled scheduling tests, not a claim
that arbitrary host exhaustion is harmless.

## Eligibility rules

Only the native incremental HNSW integration opts into complete visibility:

- Its authoritative source scan rejects pending or not-yet-visible records.
- Every committed source mutation is covered by the existing bounded journal;
  visibility floors, gaps and resets remain explicit eligibility barriers.
- The observed Raft commit must already have reached the applied watermark.
- Root, collection and index-configuration revisions must match exactly.
- Global visibility may advance only monotonically, and the journal head must
  still equal the generation's covered cursor at acquisition and final validation.
- Actual source changes still require maintenance and bounded request retries.

Manual HNSW, exact flat and other uncertified generations retain strict certificate
equality. The general certificate equality operator is unchanged. Hash collisions
in the bounded collection-revision table remain conservative invalidations.

Generation policy is published with a new metadata object sharing graph ownership;
queries do not copy the graph. Incremental graph edits still use the existing
per-index lock. This is not an implementation of immutable graph snapshots or a
new concurrent graph algorithm. Index rebuilds retain their existing readiness
and resource-budget policies.

The first ThreadSanitizer attempt reported a lock-order inversion in the test's
mock source producer. It held the same mock storage mutex required by its
certificate callback while emitting graph records. The producer now snapshots
under that mutex and releases it before emitting. Assertions and sanitizer checks
remain enabled; the first failure is preserved. This is a fixture correction,
not evidence that an observed production deadlock was fixed.

## Readiness limits

Production readiness remains **INCOMPLETE**. Short tests cannot replace the
eight-hour stability gate, independent review of the exact release candidate,
physical-power qualification, or stable platform signing/install evidence.
Resource exhaustion, unavailable generations, real mutation lag, cancellation and
query deadlines may still return explicit errors; this change must never turn
them into stale or incomplete successful results. The earlier failed load run
must remain disclosed alongside new results.
