# Native ANN service and hybrid engine integration

Status: development, INCOMPLETE for release and public rollout. This report follows
the [dense/sparse/named storage checkpoint](V1.2_DENSE_SPARSE_NAMED_VECTORS.md).
The new trusted C++ engine API is implemented; existing public RPC ANN routing
remains gated. Do not describe internal READY as production certification.

## A. Implementation

### Bounded service and cancellation

`native_vector_index_service.hpp/.cpp` implement an engine-local registry with a
fixed default of two live index managers/workers, one build slot per manager,
1 GiB shared graph/lexical allocation budget and 512 MiB source reservations.
Per-index configuration supplies tighter graph/source/scan/build-time limits.
Configuration changes require unloading the old manager. Retained managers keep
their worker/source reservation; reader-retained generations keep their graph
allocations charged. Quota exhaustion is an explicit error, not hidden fallback.

Registry locks cover short metadata operations, never source scans, graph builds,
callbacks, worker joins or final graph destruction. Unload/shutdown permanently
close managers, cancel their source/build work and join outside registry locks.
Shutdown stops index workers before the LSM flush/shutdown sequence. Root
initialization closes the previous service before changing storage context.

`hnsw_index.cpp` supports traversal-local checks on insertion and search. The
manager supplies cancellation/deadline checks inside construction; native query
supplies its own request token/time checks. Read cancellation does not poison a
healthy graph. Failed construction cannot be published or queried as healthy.
The default build budget is ten minutes; a large build may require an explicitly
larger configured budget, capped at one hour. A synthetic standalone kernel build
does not establish that a default-budget storage-backed 1M build will finish.

### Authoritative storage integration

`database_engine_vector_native.cpp` integrates definitions in the existing
`pacificdb_meta/vector_index_specs_v1` catalog, current committed LSM rows and
composite root/collection/catalog/visibility certificates. Definition reads and
candidate returns are fenced against changes. Specs remain ordinary WAL/LSM
records; graphs and postings are derived in-memory structures.

The trusted engine methods are:

- `buildNativeVectorIndex`: validate and durably configure, then queue a build.
- `rebuildNativeVectorIndex`: reconstruct from committed records.
- `nativeVectorIndexStatus`: report ABSENT/QUEUED/BUILDING/READY/STALE/FAILED,
  generation, graph/lexical health and resource counters.
- `queryNativeVectorIndex`: acquire a fresh immutable generation, search, fetch
  authoritative candidates, re-score original numbers and revalidate freshness.
- `queryNativeHybridIndex`: fuse ranked vector and BM25 results under one fresh
  generation/certificate and shared visibility/filter policy.
- `dropNativeVectorIndex` / `stopNativeVectorIndexes`: remove definitions or stop
  derived work without deleting authoritative vectors/documents.

These are trusted C++ integration/qualification entry points, not new public RPCs.
They do not replace router authorization, strong-read fencing or rollout gates.
Multi-peer catalog operations remain rejected; single-node Raft and standalone
storage use their existing committed mutation paths.

Each source scan bounds examined rows, source allocations, IDs, selected dimensions
and elapsed time. It copies only selected vector/text fields and shared visibility
metadata; it does not materialize every complete document. Source buffers, IDs,
duplicate detection and container reallocation now use a PMR source-byte budget.
The registry reserves the sum of those source caps before creating workers.
Producer input/JSON decoding and allocator overhead remain outside that allocation
counter; explicit input-size limits bound the additional per-record temporaries.
This is not a whole-process RSS guarantee.

Dense graph values are derived float32 copies. Authoritative dense/sparse numbers
are unchanged. Missing selected spaces and mismatched dense dimensions are
ineligible. Unsupported selected sparse/malformed/nonfinite/out-of-float32-range
source values fail the graph build instead of silently omitting searchable data.
Source IDs must be nonempty and at most 1,024 bytes.

### Freshness and mutations

Insert/batch/update/delete, catalog changes, replay, snapshot restore and namespace
changes invalidate prior certificates through the shared storage hooks. A stale
generation cannot serve a successful native ANN/hybrid response. The caller must
request a rebuild or use the existing exact path; public auto continues using the
safe exact policy. Heavy builds never run in the Raft acknowledgement path.

Current engine maintenance is full background reconstruction, **not completed
incremental committed graph maintenance**. The lexical component has tested
incremental upsert/delete primitives, but they are not synchronously invoked from
storage/Raft or represented as a validated index-plus-delta contract.

## B. Real lexical indexing and hybrid ranking

`lexical_index.hpp/.cpp` implement a separate derived inverted-index component with
per-term postings/frequencies, document lengths, live document frequencies,
upsert/delete handling, tombstones, memory admission and BM25 scoring. This is not
the existing substring TEXT predicate, which is unchanged.

The declared score is a sum over unique query terms of
`log(1 + (N-df+0.5)/(df+0.5)) * tf*(k1+1)/(tf + k1*(1-b+b*length/avgLength))`.
Defaults are k1=1.2 and b=0.75. The positive IDF convention is documented in
[Apache Lucene's BM25 implementation](https://github.com/apache/lucene/blob/main/lucene/core/src/java/org/apache/lucene/search/similarities/BM25Similarity.java).
This implementation does not claim bit-identical Lucene scores or analyzer
behavior. Duplicate query terms are deduplicated. N counts live indexed text
records, including records with empty text. Query terms use OR by default; an
explicit all-terms option is supported.

Tokenization lowercases ASCII letters, retains alphanumerics/contiguous high bytes
and splits on other bytes. There is no stemming, Unicode normalization, phrase
index, stop-word processing or language-specific analysis. Document text is capped
at 1 MiB/65,536 tokens; query text at 4 KiB/64 tokens. Candidate exhaustion fails
explicitly. Tombstoned postings remain charged until reconstruction compacts them.

Optional durable `text_field` / `max_lexical_bytes` settings build graph and lexical
components from the same source/certificate and publish them together. Text-only
records can participate in lexical retrieval without being inserted into HNSW.
Records missing the string text field remain eligible for vector retrieval.

Hybrid search uses validated Reciprocal Rank Fusion, configurable nonnegative
weights/rank constant and deterministic score/ID ordering. Each ranker receives an
explicit bounded candidate count (at most 1,000); final K must not exceed it. This
is fusion over those ranked lists, not exhaustive ranking over all possible ranks.
Zero weights allow a single-ranker query. Duplicate IDs within an input ranking
and invalid/nonfinite weights/scores are rejected.

Metadata-filtered or read-floor hybrid requests use exact vector ranking and
apply the shared eligibility predicate across lexical candidates before lexical
top-K retention. Selective filters therefore do not arbitrarily truncate a prefix.
All authoritative reads share explicit scan/time/cancellation/result-byte limits.
Final fetched rows are revalidated and receive the fused score. Native ANN-only
requests with unsupported filters/read contexts explicitly require exact search.
Hybrid cursor/offset pagination is rejected rather than silently ignored.

## E. Mixed-flow secondary-index repair (qualification in progress)

The new concurrent document/media/exact/ANN-build fixture also rebuilds a BTree
while updates and deletes run. ThreadSanitizer first identified collection/index
lock inversion in the existing rebuild path. Rebuild now takes the collection
read lock before the index lock and retains its source snapshot through publication.
Writes to that same collection wait during rebuilding; unrelated collections do not
share that lock.

Strict physical index validation then exposed delayed queued updates resurrecting
index entries after deletion. Pending batches now deduplicate IDs and resolve the
latest authoritative version across active/immutable memtables and published SSTs
under the collection read lock before acquiring the index lock. Tombstones remove
entries. A delayed payload is never itself authoritative. This adds point-read I/O
for indexed writes and holds the collection read lock through index publication,
so same-collection writers may also wait behind a maintenance batch. WAL formats, fsync policy and acknowledgement requirements are
unchanged. Normal mixed testing and explicit obsolete-payload replay after flush
and deletion pass. ThreadSanitizer and the full post-repair checkpoint also pass
(62 top-level checks, including 33 CTest cases).
Raw red/green logs are retained; no final rebuild masks validation failures.

## G. Distributed dependency reconfirmed

`ShardManager::migrateShard` in `engine/src/shard_manager.cpp` currently changes
primary-host metadata and immediately marks the shard ACTIVE. It does not transfer
records or perform a fenced cutover. `rebalanceShards` likewise redistributes host
metadata. The public `queryVector` handler executes a local engine query after its
existing read fence; it has no all-shard fan-out/completeness protocol. RF3
replication tests therefore must not be described as distributed vector sharding
qualification. Public distributed ANN remains gated pending real record transfer,
ownership epochs, routing and unavailable-shard completeness handling. Existing
sharding interfaces were not silently changed in this checkpoint.

## I. Reproduction and file map

Build the normal and dedicated failpoint directories using the development guide
and required system dependencies. Do not reuse production data roots. Run:

```bash
cmake --build build-v1.2-hnsw-core -j2
cmake --build build-v1.2-safety-failpoints -j2
python3 scripts/test-vector-checkpoint.py \
  --build build-v1.2-hnsw-core \
  --failpoint-build build-v1.2-safety-failpoints \
  --expected-version 1.2.0-dev \
  --evidence /tmp/v12-native-new-empty-evidence
PACIFICDB_TEST_TYPED_VECTORS=1 PACIFICDB_EXPECTED_ENGINE_VERSION=1.2.0-dev \
  node scripts/test-cross-sdk-e2e.mjs build-v1.2-hnsw-core
build-v1.2-hnsw-core/db_engine_hnsw_qualification 1000000 25 100 cosine
build-v1.2-hnsw-core/db_engine_native_vector_qualification 1000000 100
```

The checkpoint evidence directory must be empty. The scale commands create owned
scratch roots and can take tens of minutes, hundreds of MiB of derived memory and
additional source/document memory. The native diagnostic explicitly requests a
one-hour build cap and 1 GiB graph cap; defaults are smaller. Build timeouts remain
errors, not permission to silently return partial results.
