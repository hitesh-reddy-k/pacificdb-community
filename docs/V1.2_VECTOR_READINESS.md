## Compatibility boundary

The tested document/media/authentication/WAL/LSM/RF3/SDK flows have regression
evidence; that is not a claim that every existing production workload or upgrade
combination is qualified. Existing authoritative vector records still use shared
durable storage, with legacy numeric precision and formats. No graph owns those
records, and deleting a catalog definition is tested to preserve vector data.

No commit, push, publication or deployment is authorized or performed by these
checkpoints. See [development changes and reproduction](releases/1.2.0-development.md)
and each report's raw evidence for exact tested binary/source fingerprints.

## Company benchmark replay (2026-10-30)

A fresh bounded GloVe-25/1M comparison completed three repeats of ten held-out
queries. Median of run medians: public PacificDB exact 7556.13 ms, PostgreSQL
exact 81.62 ms; pgvector HNSW 1.888 ms at Recall@10 0.97. Exact results matched
independent ground truth. PostgreSQL exact was 92.6× faster in this diagnostic.
Public PacificDB ANN remains gated; there is no matched public ANN comparison.
RAM-backed scratch storage, small repeated query set and corrected measurement
order limit these results. This is a development submission, not release approval.
See [report and methodology](v1.2-evidence/company-benchmark-20261030/REPORT.md)
and [portable company bundle](PacificDB-v1.2-development-company-benchmark-20261030.zip).

## Completed public comparison — 2026-11-01

[Final report, raw evidence and provenance](v1.2-evidence/community-verified-cache-comparison-20261101/REPORT.md).
The benchmark ran the frozen `86914968...` candidate against PostgreSQL 18.6 and
pgvector 0.8.7 on shared GloVe-25 inputs with committed fsync enabled. It is a
self-run development comparison, not a published stable release or certification.

| Four 10K dimensional/metric workloads and sparse/named/hybrid capability checks | PASS | Separate supplemental raw records; hybrid rankers differ |
| 1M changed/deleted record recovery and derived ANN reconstruction | PASS | 45 changed vectors, five deletes, count 999995; ten post-rebuild queries Recall@10 0.96 |

| Error-free strict ANN reads during measured concurrent writes | FAIL | 26/360 reads versus 360/360 at 1M |
| Fast filtered retrieval at 1M | FAIL | 1% filtered exact 7031.49 ms versus 76.90 ms p50 |
| Durable ANN graph checkpoint and replay | INCOMPLETE | Definitions/vectors durable; graph reconstructs after restart |
| Full sustained/platform/upgrade/power-loss/security qualification | INCOMPLETE | Not established by these measured workloads |

Exact uses a 15.45-second packed-index build and measured 49.73 ms p50 versus
PostgreSQL 112.23 ms; both matched the reference. Initial ANN source/build took
45.82 min versus 8.03 min. After restart, PacificDB was connectable in 99.04 s and
needed 35.97 min to rebuild ANN. Repeated row-cache hits and PSS memory are recorded
per phase. No arbitrary workload, high-dimensional 1M dataset or physical power
failure is certified. Distributed completeness remains gated outside standalone
Community scope; advanced compression and graph maintenance retain separate gates.
