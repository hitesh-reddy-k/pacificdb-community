## Implemented changes

`engine/include/read_cache.hpp`, `engine/src/hnsw_index.cpp`:

- Statistics, size and dimensions now synchronize with insertion; shared locks
  permit concurrent readers while mutation takes an exclusive graph-local lock.
- Corrected random level selection to a geometric continuation probability `1/M`.
  The original repeated level-dependent probability suppressed higher levels.
- Validate graph configuration, empty/nonfinite vectors, dimensions, duplicate
  IDs and a configurable maximum node count. Zero-K queries return empty.
- Accumulate distances in double precision; clamp float output for extreme finite
  input and bound cosine roundoff. Authoritative stored vectors are unchanged.
- Removed unsupported logarithmic-complexity claims from the source header.

`engine/include/vector_index_generation.hpp`,
`engine/src/vector_index_generation.cpp` implement a deliberately disconnected
lifecycle primitive: one worker and one pending job, bounded collected source
bytes/node count, ABSENT/QUEUED/BUILDING/READY/STALE/FAILED, cooperative cancellation,
revision checks, immutable shared graph ownership and publication under a short
instance-local mutex. Source collection finishes before graph construction;
construction never holds the manager mutex. Retained generations survive swaps.
The caller must validate the authoritative certificate again after fetching rows.

This source-byte check is not a graph memory reservation: graph allocations,
allocator overhead, producer allocations and retained old generations need separate
admission accounting. Each instance owns a worker, so it is not yet the bounded
database-wide index service. A producer must cooperate with cancellation; shutdown
cannot safely interrupt arbitrary blocking callbacks. No production claim follows.

## Targeted tests

`hnsw_core_test.cpp`: independent double-precision exact ranking for all three
metrics, 2,000 rows, 32 held-out queries per workload, 12 dimensions plus cosine
64 dimensions. Each measured Recall@10 was 1.0 in the recorded run. Tests also cover
invalid config/records, extreme finite inputs, dimension inference, node limits,
concurrent insert/search/statistics. Release and ThreadSanitizer runs passed.
These small random workloads are not 10K/100K/1M qualification or a latency claim.

`vector_index_generation_test.cpp`: publication, certificate mismatch, stale build,
rebuild generation numbering, retained old readers, duplicate source failure,
source-budget failure, cooperative shutdown, certificate failure and twenty rebuilds
with four concurrent readers. Core and lifecycle ThreadSanitizer runs passed.
Registered as standalone CTest targets. Final publication/cancellation changes passed both normal and sanitizer runs.
[Targeted raw logs](v1.2-evidence/checkpoint-2-progress/) are retained.
Full engine build passed; final regression replay is recorded separately below.

## Required integration before public eligibility

1. Durable collection specifications through existing WAL/LSM/Raft records. Do not
   send a new index type through the existing B-tree-only CREATE_INDEX apply path;
   older replicas would reject it. Define mixed-version capability gating.
2. Authoritative certificates covering put, putMany, deletes, committed visibility,
   WAL replay, root restore, collection drop and schema changes. Source callbacks
   in the current tests are synthetic and provide no LSM integration proof.
3. Tenant/read-context visibility, authoritative candidate fetch, final certificate
   recheck and filtered-search fallback. Never publish a partial restored scan.
4. Database-wide memory reservations, worker quotas, bounded lifecycle registry,
   incremental mutation maintenance and graph compaction. Current core inserts are
   incremental but the generation primitive builds complete replacement graphs.
5. Neighbor-diversification evaluation and scale/recall validation. The native core
   still uses nearest-only neighbor pruning; the small recall results do not prove
   suitability on clustered/high-dimensional datasets.
6. Crash-during-build/publication, corruption/reconstruction, snapshot restore,
   concurrent writes, RF3 catch-up and 10K/100K/1M measurements.

Persistent graph files, public lifecycle APIs, incremental committed maintenance,
sparse/named vectors, hybrid and distributed retrieval remain INCOMPLETE.

## Isolated scale diagnostics (not public ANN qualification)

Fixed synthetic input seed, normalized random float32 vectors, cosine, dimension
25, M=16, efConstruction=200, efSearch=200, K=10, 100 held-out queries. Independent
double-precision exhaustive cosine ranking supplies ground truth. These runs
exercise the repaired graph class directly, bypassing storage, authorization,
filtering, network, recovery and freshness. Concurrent compilation/regression work
means timings are diagnostic only and cannot support a baseline speedup claim.

| Rows | Recall@10 | Graph build seconds | Query median milliseconds |
| --- | ---: | ---: | ---: |
| 10,000 | 1.000 | 6.187 | 0.984 |
| 100,000 | 0.994 | 140.173 | 1.620 |

Raw diagnostic sources/results are in the checkpoint evidence directory. Example:
`g++ -std=c++17 -O3 -pthread -Iengine/include docs/v1.2-evidence/checkpoint-2-progress/repaired-hnsw-100k.cpp engine/src/hnsw_index.cpp -o /tmp/pacificdb-hnsw-100k`
then run `/tmp/pacificdb-hnsw-100k`. Input generation is seeded; graph levels use
nondeterministic randomness, so individual runs can differ. No full RSS sampling,
throughput, persistent disk-size or ingestion-impact result is claimed. 1M ANN,
clustered/high-dimensional scale, and mixed durable workloads remain INCOMPLETE.
The earlier 1M exact replay is a separate durable workload and must not be compared
to these isolated graph timings as a database-level ANN speedup.
