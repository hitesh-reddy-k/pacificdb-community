# Native dense, sparse and named vector records

Development checkpoint on `v1.2`. Implemented storage/query capabilities below
are distinct from full production readiness. Public ANN remains gated.

## Record formats and authoritative storage

Legacy dense vectors remain JSON numeric arrays. Their numeric values are not
silently narrowed to float32. Existing dense exact queries retain their optimized
distance kernel. New sparse values have an explicit, versioned representation:

```json
{
  "format": "sparse-v1",
  "precision": "float64",
  "dimensions": 1000000,
  "indices": [3, 999999],
  "values": [0.125, -2.0]
}
```

Indices must be integers in range, sorted and unique. Values must be finite
numbers. Shapes must match. Empty indices/values represent a zero sparse vector.
Declared dimensions range from 1 to 1,000,000,000; at most 1,000,000 stored values
are accepted. Exact sparse scoring does not allocate a dense vector of that size.
The object has exactly the five documented keys; unknown formats/precision or
extra keys fail dedicated vector-write/query validation.

Sparse records store only index/value arrays, not a dimension-sized zero array.
The authoritative encoding is the existing document MessagePack/SST format carrying
this typed object; WAL retains ordinary document mutations. This checkpoint does
not introduce a second store, external vector files, a new SST version, float32
migration, or a specialized packed sparse blob. Existing WAL/SST checksums cover
the ordinary encoded record bytes. JSON round trips retain the declared values.

Multiple spaces can be stored in a record's `vectors` object:

```json
{
  "id": "article-1",
  "category": "news",
  "vectors": {
    "semantic": [0.25, 0.75],
    "terms": {
      "format": "sparse-v1", "precision": "float64", "dimensions": 1000000,
      "indices": [3, 999999], "values": [0.125, -2.0]
    }
  }
}
```

The legacy default `vector` field may coexist with `vectors`. Up to 64 named spaces
and 1,000,000 total numeric values per dedicated vector-write record are accepted.
Names are 1–128 UTF-8 bytes without NUL and are literal keys, not dotted paths.
The payload stays an ordinary document, so metadata, versioning and tombstones
use the existing shared mutation and replication lifecycle.

## Public operations

The existing `insertVector` action accepts `data.vector`, `data.vectors`, or both.
It validates all provided vector spaces before submitting the existing insert
mutation; invalid vector payloads cannot be partially stored. No new RPC is needed.

```js
await db.request({ action: 'insertVector', collection: 'articles', data: {
  id: 'article-1', category: 'news', vectors: {
    semantic: [0.25, 0.75],
    terms: { format: 'sparse-v1', precision: 'float64', dimensions: 1000000,
      indices: [3, 999999], values: [0.125, -2] }
  }
}});
const results = await db.queryVector('articles', [0.25, 0.75], {
  vectorName: 'semantic', searchMode: 'exact', k: 10,
  metric: 'cosine', filter: { category: 'news' }
});
```

Node `putVector`/`queryVector` also accept the sparse object. Node's additive
`vectorName` maps to wire `vector_name`; omitted options preserve existing wire
behavior. Python and Java advanced vector operation maps accept the same wire
fields and JSON shapes. Existing SDK binding contracts are preserved.

Retrieval by ID, updates, upserts and deletes remain existing document operations.
Batch ingestion remains existing `insertMany` with the same record shapes. This
checkpoint does **not** add collection schema enforcement to generic document CRUD
or batches. Such operations can store arbitrary payloads; callers needing dedicated
validation should use `insertVector`. Future collection-level validation must cover
every committed mutation path before claiming enforced vector schemas.

`queryVector` accepts a dense array or sparse-v1 value in `vector`. If
`vector_name` is provided it searches only that literal key under `vectors`.
Without it, it searches only the legacy default `vector` field. No cross-space
fallback or automatic space fusion occurs. Missing spaces and dimension mismatches
are ineligible, as with historical dense dimension mismatch behavior. Malformed
vector payloads stored through generic document CRUD are ineligible; invalid query
or dedicated vector-write inputs fail. Zero sparse cosine similarity is defined as
zero. Sparse/dense cross-representation scoring is supported for equal dimensions.

Exact metrics are dot product, cosine, and negative Euclidean distance (higher
scores rank first). Sparse scoring uses a merged index traversal and extended
accumulation; results are float64. Finite inputs whose computed score cannot be
represented fail with `vector_score_out_of_range`. Deterministic score/ID ties,
bounded top-K, scan/byte limits, cancellation, tenant filtering and read-floor
checks continue through the existing exact executor. Sparse support does not
enable sparse HNSW or a new approximate-result contract.

## Files and tests

`vector_value.hpp` defines validation and sparse/mixed exact distance calculation.
`database_engine.cpp` integrates dedicated validation, space selection and exact
scoring without changing the dense array fast kernel. Node validation and tests
cover sparse shapes and the additive name option. Existing RF3 tests now cover
named/sparse committed insert/update/delete and follower catch-up.

Targeted results:

- `vector_value_test.cpp`: 1,000 independently densified random sparse pairs across
  all metrics, zero vectors, one-billion-dimensional single-nonzero vectors,
  shape/index/finite-value rejection; normal and ASan/UBSan PASS.
- `vector_named_sparse_storage_test.cpp`: multiple spaces, default space, filters,
  tenant isolation, dimension/missing behavior, SST flush, overwrite/delete,
  snapshot restore, WAL replay and strong read floors PASS. Four readers during
  80 updates validate score/payload consistency; normal and ThreadSanitizer PASS.
- `vector_named_sparse_crash_test.cpp`: two acknowledged writes followed by SIGKILL
  without explicit SST flush; restart recovers both from WAL and preserves double
  precision. PASS on Linux; POSIX-only fixture explicitly skips on Windows.
- Enhanced real RF3 suite: named sparse insert/update/delete survive follower
  restart/catch-up; PASS in the targeted run.
- Existing dense exact/correctness tests and Node/CLI suites PASS. Capability
  contract check PASS for all 135 existing dispatch bindings.

Initial build attempts failed because prior extracted development headers had
been removed from `/tmp`. Dependencies were restored to the isolated temporary
prefix; the missing Abseil-header failure is retained. No dependency or compiler
gate was disabled. Full regression results are recorded separately when complete.

## Remaining qualification

Collection schemas, specialized compact typed encoding/migration, named/sparse ANN,
rank fusion across spaces, full public ANN lifecycle, incremental index maintenance,
hybrid retrieval, distributed vector coordinator and full scale/release qualification
remain INCOMPLETE. Existing source/read compatibility is not a promise that old
engines can execute new sparse/named queries. Mixed-version feature negotiation and
rolling-upgrade qualification are still required before enabling such use in a
production cluster. No ingestion/latency/RSS improvement is claimed by this checkpoint.

## Final implementation / validation report

**Implementation:** native dense/sparse/named record validation and exact search
are implemented through shared authoritative records. Node helpers are additive.
Generic document CRUD and batches retain their existing flexible-document behavior;
this checkpoint does not claim enforced collection-level vector schemas.

**Testing — PASS for stated scope:** complete Release build, dedicated failpoint
build, all **58 top-level checkpoint checks**, including **27 CTest cases**.
Existing document/media/secondary-index/authentication/WAL/LSM/snapshot/crash/RF3/
partition/restart tests passed. Existing Node/CLI tests passed; all 135 dispatch
bindings passed the SDK capability check. Normal and ThreadSanitizer tests of four
concurrent named-vector readers and 80 updates passed. The independent sparse-value
test passed ASan/UBSan. No sanitizer suppression was introduced.

Both the original Python/Java live replay and an explicit
`PACIFICDB_TEST_TYPED_VECTORS=1` replay passed authenticated TCP/TLS, sparse/named
querying, exact double-value round trips and SIGKILL recovery. The opt-in fixtures
preserve compatibility with older released-engine test runs when the new flag is
omitted. No mixed-version rolling-upgrade qualification is implied.

**Failures:** the retained initial build failed because temporary RE2 dependencies
were absent. After restoring SSL/RE2/LZ4/Abseil development headers, all final builds
and tests passed. No final test in this checkpoint failed or was blocked on Linux.
Windows SIGKILL fixture is explicitly unexecuted/skipped; do not count it as PASS.

**Performance:** no new benchmark or full-scale qualification was executed for this
storage/query revision. Sparse scoring is implemented with a merged nonzero
traversal; no latency, throughput or RSS improvement is claimed without measurement.
Historical dense exact and isolated HNSW numbers remain attached to their original
fingerprints and must not be relabeled as measurements of this revision.

**Reliability:** exercised dense/sparse/named records remain authoritative in shared
WAL/LSM, recover after SIGKILL and snapshot replay, and replicate through RF3. Named
space selection retains row-tenant/read-floor/filter/cancellation/limit behavior.
This is not a completed ANN, lexical/hybrid or distributed-query consistency proof.
