# Incremental ANN: implementation contract and release gates

Status: **INCOMPLETE**. This extends the existing source-certified native service;
it does not replace WAL/LSM, Raft or immutable full-build publication.

## Committed-source coverage

An incremental worker needs a bounded, replica-local sequence of every source
mutation since its published generation. The sequence is derived and disposable.
Missing history, overflow, restore, dropped namespaces or ambiguous visibility must
invalidate eligibility and require a rebuild; no failed enqueue may silently lose
coverage. Capture a certificate before/after reading history. Resolve changed IDs
from authoritative latest committed records, including tombstones, and revalidate
the target certificate before publication. Do not assume insertVector is the only
write path: generic CRUD, batch, apply and restore also mutate vectors.

The history stores IDs and source visibility requirements, not a second vector
store. It must be bounded by allocation accounting, maximum subscriptions and
changes, and record explicit overflow. Subscribe before the build's starting
certificate. An unchanged full-build certificate then anchors a matching history
cursor. Hash collisions may conservatively force rebuilds; never establish false
coverage. Committed visibility changes without row edits must not expose pending
rows missing from the graph.

## Incremental graph strategy

The HNSW core now appends replacement nodes and tombstones previous versions.
Deleted nodes remain navigation bridges but are excluded from final hits. The
live-ID map contains one version per ID. Physical node history and PMR allocation
are bounded; reaching capacity requires compaction/rebuild. Initial tests cover
replacement/deletion/reinsertion, live cardinality, three metrics, independent
post-update exact ground truth and concurrent readers. This core result does not
qualify a committed maintenance service.

Heavy updates execute on a bounded index worker. No graph construction occurs in
WAL/Raft acknowledgement. Per-index graph locks coordinate search and maintenance;
source certificates reject queries crossing committed changes. Only a successfully
covered target revision can become READY. Failure after a partial graph mutation
must poison that generation and force safe fallback/error. Existing reader
references must remain safe and charged. Queries may never return deleted IDs or
old vectors simply because maintenance lags.

Lexical hybrid generations and exact flat generations need their own compatible
maintenance/compaction behavior. Until separately implemented they remain stale
on source mutation. No HNSW-only maintenance claim includes those plans.

## Required validation

History coverage/overflow/root reset and stale cursor rejection; batch atomic
coverage; committed/uncommitted visibility; insert/upsert/update/delete through all
write paths; concurrent queries and mutations; shutdown/restart; crashes during
maintenance; snapshot/restore; replica catch-up/election; dimension/metric/schema
changes; no cross-tenant leakage; bounded memory/queue; physical-history
compaction; 10K/100K/1M held-out recall and latency/write-impact measurements.
The production release remains INCOMPLETE until these gates pass.


The bounded journal, LSM observation hooks, existing-worker incremental mode and
schema-constrained standalone integration are now implemented. See the
[implementation and qualification report](V1.2_SCHEMAS_AND_INCREMENTAL_ANN.md).
Full production qualification and automatic compaction remain incomplete.


The current opt-in HNSW-only integration now observes LSM single/batch puts and
tombstones, requires configured dense spaces, resolves source IDs on the existing
worker, refuses pending source omissions and revalidates journal coverage at
publication. Snapshot/root/collection invalidation and explicit history-gap
failure are tested. Automatic graph compaction, multi-peer capability/upgrade and
complete sustained-load qualification remain open gates.
