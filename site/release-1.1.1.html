What changes in the candidate

Added

  • Direct PacificDB.connect(url) entry points for Node.js, Python and Java, with authenticated URLs, verified TLS and explicit connection lifecycles.
  • Python and Java document CRUD, bulk, aggregation, explain and named operation families.
  • Python and Java checksummed, bounded file uploads/downloads and full backup export, with explicit resume IDs.
  • Workbench database URLs and matching CLI/SDK connection examples.

Removed

  • Mandatory project selection from database and collection workflows.
  • Friendly project commands in native/npm shells and project screens in Workbench.
  • Stored project IDs and tokens from updated CLI context. Legacy engine and SDK project APIs remain available.

Improved

  • Database creation selects after success. Database switching checks the authorized catalog.
  • Java/Python clients pool connections, preserve request scope, expose typed errors and close pending work.
  • Fixed Node.js pool scheduling after sequential warmup: completed slots become available before caller promises settle, letting a concurrent burst use the configured connections. A peer regression verifies four concurrent requests with a four-connection pool.
  • Media transfer validates chunks and whole files; verified downloads replace destinations only after successful checks.
  • Workbench limits Overview count work and stops scheduling it when another view is selected.

Measured performance and trade-offs

Three fresh-data rounds compared the exact public 1.0.0 Debian engine and npm SDK with the local 1.1.1 candidate on the same Linux host. Read median throughput changed from 3,850.9 to 19,990.6 calls/s, low-cardinality index rebuild from 4.9 to 21.6 calls/s, and vector search from 845.9 to 906.2 calls/s. Every retained run passed field-by-field integrity and SIGKILL recovery checks.

The result is not uniformly faster. Batch-10 changed from 756.8 to 237.5 calls/s, batch-1,000 from 35.7 to 32.4 calls/s, delete P99 rose from 20.859 to 23.888 ms, and mixed P99 rose from 10.822 to 13.135 ms. RF3's median paired change was +4.82%, but a severe baseline outlier makes that too variable for a headline RF3 claim. See the engineering report for method, all runs, resource counters, bottlenecks and limitations.

Try the database-first flow

Build the prepared candidate checkout using the source instructions, then run ./build/pacificdb. Use a fresh database name:

create database app
create collection users
insert users {"id":"1","name":"Ada"}
find users {"id":"1"}

For an existing database use use app or pacificdb --url 'pacificdb://127.0.0.1:9000/app' --no-start. A database URL speaks the engine protocol; browser Workbench uses its separate printed HTTP address.

Workbench: candidate versus published 1.0.1

The published preview groups databases under projects. Candidate navigation lists databases directly, creates/selects a database without a project, and nests collections under that database. Existing project-mapped databases remain accessible without moving stored data.

The candidate connection dialog requires a selected database and generates its database URL, native CLI command and Node.js/Python/Java examples. Authenticated examples read PACIFICDB_URL privately; credentials are omitted from copied examples.

Overview loads missing collection counts through one loader with at most four jobs in flight, caches results per database, invalidates affected summaries after mutations, and displays a dash when totals are incomplete. Documents, Query and Media views do not initiate full collection count scans. This bounds background work; it is not a measured startup-speed claim. Query durations include the Workbench transport and engine.

The current Debian after-install hook registers the launcher and sets the Chromium sandbox helper to root ownership and mode 4755. Source development on Linux may need the manual helper setup. Published preview downloads remain available; candidate desktop packaging still requires qualification.

Compatibility and limits

No project/data migration is required. Legacy createProject/useProject and raw project/catalog actions remain available for existing consumers. Creation is explicit and not idempotent. Use matching candidate SDK packages for new convenience methods.

Interrupted writes can have unknown outcomes and are not retried automatically. File transfers use explicit resume IDs; practical file limits remain disk, network, and request constraints. Workbench uploads have a 64 MiB UI limit. Community indexing remains non-unique, single-field B-tree indexing.

Use Node.js, Python, Java, CLI, and Workbench guides for install, authentication, CRUD, vectors, media, closing and troubleshooting. The 1.0.1 source notes remain historical.
