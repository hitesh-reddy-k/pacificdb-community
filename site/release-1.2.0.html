V1.2 RELEASE · VERSION1.2.0

One database.
More ways to search.

PacificDB v1.2 combines documents, vectors and media using shared authoritative WAL/LSM storage.

Release and packages · SHA-256 checksums · Installation. Targets: Ubuntu24.04 x64, Windows x64, macOS15 Intel and Apple Silicon. Windows/macOS installers are unsigned and macOS is not notarized.

What changed in v1.2?

Added

  • Persistent dense, sparse and named vectors with creation-time schemas and matching SDK operations.
  • Standalone exact/HNSW indexing, bounded dense incremental maintenance and lexical/vector hybrid retrieval with BM25 and reciprocal rank fusion.
  • Workbench terminal command setup, including automatic Windows installer PATH registration.

Removed

  • Unsafe legacy all-pairs ANN selection from supported query routing.
  • Process-global query-limit state that could mix concurrent requests.

Improved

  • Bounded exact ranking, selective vector decoding and visibility-aware point reads.
  • Incremental ANN freshness across concurrent commits and bounded waiting for strict reads.
  • Idle SDK connection handling, credential-file validation and Linux launcher integration.
  • Consistent offline version reporting and package installation tests.

Install and integrate

Workbench installers bundle the engine and native CLI. Node.js and npm CLI packages use version1.2.0; Python uses pacificdb==1.2.0. Java is downloadable as a JAR and matching POM with coordinates in.pacificdb:pacificdb-client:1.2.0; imports remain io.pacificdb.*. Maven Central publication is deferred.

Use the Python client from FastAPI and the Node.js client from a Next.js Node server runtime. The Node package is JavaScript ESM and does not ship TypeScript declarations. Keep database credentials on the server.

Back up before upgrading. Existing WAL/LSM formats and document/media APIs are retained. Legacy authenticated databases without owners may need explicit administrator ownership and grant review. Regex filters use RE2; backreferences/lookarounds are rejected.

Supported scope and compatibility

Native vector administration is an explicit standalone configuration. Exact and ANN requests have defined readiness, freshness and fallback policies. Derived indexes are rebuilt after restart; budget time and memory for reconstruction. Collection schemas are immutable at creation. Sparse/flat/lexical incremental maintenance, automatic graph compaction, complete distributed sharded vector search and compressed/disk ANN are outside this release’s supported vector scope.

Platform and workload verification apply to the recorded versions and configurations. Choose settings and resource budgets for your own workload; see the testing guide.

Benchmarks

Compare equivalent datasets, durability settings, recall targets and filters. Historical reports retain their original software versions and are not new 1.2.0 results. See the reproducible PostgreSQL + pgvector and Qdrant methodology. Measurements depend on dimensions, hardware, cache, payload and concurrency.
