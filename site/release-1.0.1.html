PacificDB Community · v1.0.1 source update

A clearer path from project to first document.

Version 1.0.1 makes the project → database → collection order explicit in the native shell, npm shell, and Node.js client creation helpers. The first run is shorter, and the shell no longer presents unused sign-in commands.

Download status: This page describes the 1.0.1 source update. The website's installer buttons and npm latest still provide published 1.0.0 packages. Build this checkout to test 1.0.1 until new packages are published.
Testing status: A local restart matrix still fails a durability assertion: an updated document reads correctly before a graceful restart but returns its earlier value afterward. This is under investigation.

What changed

Added

  • Node.js helpers to create and select projects and select a database: createProject, useProject, and useDatabase.
  • A direct Quick Start in the README and this release page on the website.

Removed

  • login, whoami, and logout from both interactive shells.
  • Saved CLI session tokens. Opening an older shell context removes its stored token.

Improved

  • Project selection is required before database creation and selection; a database in that project is required before collection creation.
  • Creation checks stale project and database mappings before sending a schema change.
  • README, website, and shell examples now follow the same v1.0.1 flow.

Try the new flow

Run the CLI built from the 1.0.1 source. Replace project_... with the ID returned by the first command.

create project demo
use project project_...
create database app
use app
create collection users
insert users {"id":"1","name":"Ada"}
find users {"id":"1"}

For existing applications

Code that calls the Node.js createDatabase or createCollection helper now needs a selected project and its mapped database. Use createProject for a new project, or useProject and useDatabase for existing data. Raw protocol requests and other SDKs still use the engine's existing API.

Engine authentication and the Node.js authentication API remain available for deployments that need them. API key commands remain in the shell.
