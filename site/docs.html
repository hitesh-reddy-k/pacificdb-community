PACIFICDB v1.0 DOCUMENTATION

Build with PacificDB.

Install a self-hosted database, work in its interactive shell, connect Node.js applications today, and use the same documentation surface for documents, vectors, media, backups, security, and operations.

Start the quickstartBrowse commands
Before critical use

v1.0 is intended for evaluation, development, staging, and controlled early-adopter deployments while external certification gates remain open. Review the certification report before storing critical data.

START HERE

Install PacificDB

The native packages include the database engine and native CLI. Choose the package matching your operating system and processor.

Linux: Ubuntu and Debian

Download the x86-64 .deb from the beta.13 release, then install it with APT.

Terminal
sudo apt install ./pacificdb-community-0.1.0-beta.13-linux-amd64.deb
pacificdb --version
pacificdb

Windows

  1. Download pacificdb-community-0.1.0-beta.13-windows-x64.exe.
  2. Open the installer and complete its steps.
  3. Open a new Command Prompt and run pacificdb.

macOS

  1. Download the Apple silicon macos-arm64.pkg or Intel macos-x86_64.pkg.
  2. Open the package and complete the installer.
  3. Open Terminal and run pacificdb.
Unsigned beta installers

Windows signing and macOS signing/notarization are pending. Verify every package using the release SHA-256 manifest.

npm CLI and Node.js client

Node.js 18 or newer is required. After publication, PacificDB v1.0 uses the npm latest tag for both the CLI and Node.js client.

Terminal
npm install --global @pacificdb/cli@latest
npm install @pacificdb/client@latest

The npm CLI is a client; installing it does not install the engine.

Docker

Terminal
git clone https://github.com/hitesh-reddy-k/pacificdb-community.git
cd pacificdb-community
docker compose up -d --build database
docker compose run --rm shell

Data remains in the pacificdb-data volume.

Build from source

Terminal
git clone https://github.com/hitesh-reddy-k/pacificdb-community.git
cd pacificdb-community
cmake -S engine -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
./build/pacificdb

FIRST DOCUMENT

Quickstart

Run pacificdb. On a loopback connection, the native CLI starts the local engine automatically when it is not already running, then opens the shell.

PacificDB shell
create project demo
list projects
create database hello
use hello
create collection ideas
insert ideas {"id":"first","title":"Hello PacificDB"}
find ideas {"id":"first"}
Local defaults

Local mode binds to 127.0.0.1:9000 and starts with authentication disabled. Configure authentication and TLS before exposing the engine to a network.

IDENTITY

Authentication

The automatic loopback launcher does not require a login. An engine configured with authentication requires a username and password once per shell context.

PacificDB shell
login admin
Password:
whoami
logout

Password input is excluded from shell history. Applications use authentication or an active API key.

ORGANIZE

Projects

Projects organize local database names. They do not create a hosted account or change the database authorization boundary.

CommandBehavior
create project <name>Create project metadata and return its canonical ID.
list projectsList visible projects.
use project <id>Select an existing canonical project ID and clear the prior database selection.
show projectShow the current project.
delete project <id>Delete the project and its database mappings.

STRUCTURE

Databases and collections

CommandBehavior
create database <name>Create a database and map it to the selected project when present.
list databasesList databases visible in the active project context.
use <name>Select an existing database.
show databaseList collections in the selected database.
drop database <name>Drop a user database.
create collection <name>Create a collection.
list collectionsList collections.
Reserved namespace

pacificdb_meta stores Community metadata through protected engine actions.

READ AND WRITE

Documents and queries

Document commands accept JSON objects directly in the shell.

PacificDB shell
insert users {"id":"1","name":"Ada","active":true}
find users {"active":true}
findOne users {"id":"1"}
update users {"id":"1"} {"name":"Ada Lovelace"}
count users {"active":true}
delete users {"id":"1"}

Bounded aggregation

The Community aggregation pipeline supports $match, inclusion $project, sort, $skip, $limit, and terminal $count.

PacificDB shell
aggregate users [{"$match":{"active":true}},{"$project":{"name":1}},{"$sort":{"name":1}},{"$limit":10}]
explain users {"id":"1"}

Node.js

The Apache-2.0 Node.js client requires Node.js 18+. Start the native engine first, then connect over JSON/TCP.

hello.mjs
import { PacificDBClient } from '@pacificdb/client';

const db = new PacificDBClient({
  host: '127.0.0.1', port: 9000, database: 'app'
});

await db.createDatabase();
await db.createCollection('events');
await db.insert('events', { id: 'event-1', type: 'signup' });
console.log(await db.find('events', { type: 'signup' }));

DATA OPERATIONS

Backups and restore

Community backups are operator-triggered full snapshots. Restore runs synchronously and records completed and failed attempts.

PacificDB shell
create backup --name before-upgrade
list backups
show backup backup_...
backup verify backup_...
backup export backup_... ./before-upgrade.json
restore backup backup_...
list restores
delete backup backup_...

DATA OPERATIONS

API keys

Keys can use the read, readwrite, or admin role. Creation and revocation require an administrator.

PacificDB shell
create api-key --name application --role readwrite
list api-keys
show api-key key_...
revoke api-key key_...
Copy once

The complete key appears only when created. Store it in a secret manager and never commit it to source control.

DATA OPERATIONS

Media files

Images, GIFs, audio, video, and arbitrary files transfer sequentially in bounded Base64-safe chunks. Every chunk and completed file is verified with SHA-256.

PacificDB shell
upload video ./demo.mp4 --collection videos
list media
show media media_...
download media media_... ./downloaded.mp4
upload media ./large.bin --collection files --resume media_...
media cleanup media_...

PacificDB applies no application-level total file-size cap. Available disk space, request limits, network time, and machine resources still limit transfers.

DATA OPERATIONS

Vector search

Vectors must be non-empty arrays of finite numbers. Query k must be a positive integer. Supported metrics include cosine, L2/euclidean, dot, and dot product.

PacificDB shell
put vector embeddings item-1 [0.2,0.8]
put vector embeddings item-2 [0.8,0.2]
query vector embeddings [0.2,0.8] --k 5 --metric cosine

Node.js vector API

JavaScript
await db.putVector('embeddings', 'hero-vector', [0.2, 0.8], {
  modality: 'image', assetId: 'hero'
});
const matches = await db.queryVector('embeddings', [0.2, 0.8], {
  k: 5, filter: { assetId: 'hero' }
});

OPERATE

Security checklist

  • Keep development mode bound to 127.0.0.1.
  • Enable authentication and TLS before accepting network connections.
  • Give applications the smallest API-key role they need.
  • Store passwords and API keys outside source code and logs.
  • Restrict filesystem access to PacificDB data and backup roots.
  • Verify backups and perform restoration drills on isolated data roots.

OPERATE

Troubleshooting

port 9000 is in use by a service that is not PacificDB

Stop that program or start PacificDB on another port, for example pacificdb --port 9001.

The CLI asks for a login

A login prompt means the CLI connected to an engine configured with authentication. Check the selected host and port with context show.

The npm CLI cannot start the engine

The npm package contains the client shell only. Install a native PacificDB package, start the engine separately, or connect with --no-start.

select a database with: use <name>

Create or select a database before collection, document, media, or vector commands.

A project cannot be selected

use project expects the canonical ID returned by create project or list projects.
