COMMUNITY BETA DOCUMENTATION

Build with PacificDB.

Install a self-hosted database, work in its interactive shell, and connect applications using the supported clients. This guide documents the public Community beta.11 surface.

Start the quickstartBrowse commands →
Before critical use

Beta.11 is intended for evaluation, development, staging, and controlled early-adopter deployments. Review the certification report before storing critical data.

START HERE

Install PacificDB

The native packages include both the database engine and the native CLI. Choose the package matching the operating system and processor.

Linux: Ubuntu and Debian

Download the x86-64 .deb from the beta.11 release, then install it with APT.

Terminal
sudo apt install ./pacificdb-community-0.1.0-beta.11-linux-amd64.deb
pacificdb --version
pacificdb

Windows

  1. Download pacificdb-community-0.1.0-beta.11-windows-x64.exe.
  2. Open the installer and complete its steps.
  3. Open a new Command Prompt and run pacificdb.

macOS

  1. Download the Apple silicon macos-arm64.pkg or Intel macos-x86_64.pkg.
  2. Open the package and complete the installer.
  3. Open Terminal and run pacificdb.
Unsigned beta installers

Windows code signing and macOS notarization are pending. The operating system may show an unknown-publisher security prompt. Verify the file using the release SHA-256 manifest.

npm CLI and Node.js client

Node.js 18 or newer is required. The public npm beta tag installs 0.1.0-beta.11 for both the CLI and Node.js client.

Terminal
npm install --global @pacificdb/cli@beta
npm install @pacificdb/client@beta

The npm CLI is a client. Installing it does not install the engine. Automatic startup works when a native db_engine executable is already available on PATH.

Docker

Terminal
git clone https://github.com/hitesh-reddy-k/pacificdb-community.git
cd pacificdb-community
docker compose up -d --build database
docker compose run --rm shell

Data remains in the pacificdb-data volume. docker compose down stops the containers; add -v only when you intend to delete the volume.

Build from source

Source builds require CMake 3.20+, a C++17 compiler, OpenSSL, LZ4, and Node.js 18+.

Terminal
git clone https://github.com/hitesh-reddy-k/pacificdb-community.git
cd pacificdb-community
cmake -S engine -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
./build/pacificdb

FIRST DOCUMENT

Quickstart

Run pacificdb. On a loopback connection, the native CLI starts the local engine automatically when it is not already running, then opens the shell.

PacificDB shell
create project demo
list projects
create database hello
use hello
create collection ideas
insert ideas {"id":"first","title":"Hello PacificDB"}
find ideas {"id":"first"}

A successful database selection changes the prompt to pacificdb:hello>. Use help to display commands and quit to leave the shell. Leaving the shell does not stop the background engine.

Local defaults

Local mode binds to 127.0.0.1:9000 and starts with authentication disabled. Configure authentication and TLS before exposing the engine to a network.

IDENTITY

Authentication

The automatic loopback launcher does not require a login. An engine configured with authentication requires a username and password once per shell context.

PacificDB shell
login admin
Password:
whoami
logout

Password input is excluded from shell history. Session credentials and CLI context are stored with owner-only file permissions. Applications call their SDK authentication method or use an active API key.

ORGANIZE

Projects

Projects organize local database names. They do not create a hosted account or change the database authorization boundary.

CommandBehavior
create project <name>Create project metadata and return its canonical ID.
list projectsList visible projects.
use project <id>Validate and select an existing canonical project ID, then clear the prior database selection.
show projectShow the currently selected project.
delete project <id>Delete the project and its database mappings.

Use the ID returned by create project with use project. An unknown ID returns an error and preserves the previous context.

STRUCTURE

Databases and collections

CommandBehavior
create database <name>Create a database and map it to the selected project, when present.
list databasesList databases mapped to the selected project, or all user databases when no project is selected. Reserved databases are hidden.
use <name>Select an existing database within the active project.
show databaseList collections in the selected database.
drop database <name>Drop a user database.
create collection <name>Create a collection in the selected database.
list collectionsList collections in the selected database.
Reserved namespace

pacificdb_meta stores Community metadata through protected engine actions. Ordinary database requests cannot read or modify it.

READ AND WRITE

Documents and queries

Document commands accept JSON objects directly in the shell. Quote property names and use valid JSON values.

PacificDB shell
insert users {"id":"1","name":"Ada","active":true}
find users {"active":true}
findOne users {"id":"1"}
update users {"id":"1"} {"name":"Ada Lovelace"}
count users {"active":true}
delete users {"id":"1"}

Bounded aggregation

The Community aggregation pipeline supports $match, inclusion $project, single- or multi-field $sort, nonnegative $skip, positive $limit, and terminal $count. Unsupported stages fail explicitly.

PacificDB shell
aggregate users [{"$match":{"active":true}},{"$project":{"name":1}},{"$sort":{"name":1}},{"$limit":10}]
explain users {"id":"1"}

explain reports the actual equality-index lookup or full-scan choice without inventing index names.

APPLICATION SDK

Node.js

The Apache-2.0 Node.js client requires Node.js 18+. Start the native engine first, then connect over JSON/TCP.

hello.mjs
import { PacificDBClient } from '@pacificdb/client';

const db = new PacificDBClient({
  host: '127.0.0.1', port: 9000, database: 'app'
});

await db.createDatabase();
await db.createCollection('events');
await db.insert('events', { id: 'event-1', type: 'signup' });
console.log(await db.find('events', { type: 'signup' }));

For an authenticated engine, call await db.authenticate(username, password) before data operations.

APPLICATION SDK

Python

The current Python SDK is installed from the checked-out source tree.

Terminal
python -m pip install ./sdk/python
app.py
from pacificdb import PacificDBClient

db = PacificDBClient(database="app")
db.create_collection("events")
db.insert("events", {"id": "event-2", "type": "purchase"})
print(db.find("events", {"type": "purchase"}))

For an authenticated engine, call db.authenticate(username, password) first.

APPLICATION SDK

Java

The Java 11+ client is currently built from source with Maven.

Terminal
mvn -f sdk/java/pom.xml package
Java
import io.pacificdb.PacificDBClient;
import java.util.Map;

var db = new PacificDBClient("127.0.0.1", 9000, "app");
var result = db.request(Map.of(
    "action", "find",
    "collection", "events",
    "filter", Map.of("type", "signup")
));
System.out.println(result);

DATA OPERATIONS

Backups and restore

Community backups are operator-triggered full snapshots. Restore runs synchronously and records completed and failed attempts.

PacificDB shell
create backup --name before-upgrade
list backups
show backup backup_...
backup verify backup_...
backup export backup_... ./before-upgrade.json
restore backup backup_...
list restores
delete backup backup_...

backup export writes a self-contained JSON document containing every physical backup file in bounded, checksummed chunks. Store exports on separate durable storage and test restoration before relying on them.

DATA OPERATIONS

API keys

Keys can use the read, readwrite, or admin role. Creation and revocation require an administrator.

PacificDB shell
create api-key --name application --role readwrite
list api-keys
show api-key key_...
revoke api-key key_...
Copy once

The complete pdb_... key appears only when created. PacificDB persists only its identifier and secret hash. Store the key in a secret manager and never commit it to source control.

DATA OPERATIONS

Media files

Images, GIFs, audio, video, and arbitrary files transfer sequentially in bounded Base64-safe chunks. Every chunk and completed file is verified with SHA-256.

PacificDB shell
upload video ./demo.mp4 --collection videos
list media
show media media_...
download media media_... ./downloaded.mp4
upload media ./large.bin --collection files --resume media_...
media cleanup media_...

PacificDB applies no application-level total file-size cap. Available disk space, request limits, network time, and machine resources still limit transfers. Resume requires the incomplete media ID. Cleanup deletes only incomplete uploads; ready media uses delete media.

DATA OPERATIONS

Vector search

Vectors must be non-empty arrays of finite numbers. Query k must be a positive integer. Supported metrics are cosine, l2, euclidean, dot, and dot_product.

PacificDB shell
put vector embeddings item-1 [0.2,0.8]
put vector embeddings item-2 [0.8,0.2]
query vector embeddings [0.2,0.8] --k 5 --metric cosine

Node.js vector API

JavaScript
await db.putVector('embeddings', 'hero-vector', [0.2, 0.8], {
  modality: 'image', assetId: 'hero'
});
const matches = await db.queryVector('embeddings', [0.2, 0.8], {
  k: 5, filter: { assetId: 'hero' }
});

OPERATE

Configuration and local files

Connect to another engine

Terminal
pacificdb --host db.example.internal --port 9000 --no-start
pacificdb --host db.example.internal --port 9000 ping --no-start

The CLI automatically starts an engine only for loopback hosts. Use --no-start when it must connect only to an existing engine.

Engine home

PlatformDefault location
Linux${XDG_DATA_HOME:-$HOME/.local/share}/pacificdb
macOS~/Library/Application Support/PacificDB
Windows%LOCALAPPDATA%\PacificDB

The home contains data, backup, restore, engine.log, and engine.pid. Set PACIFICDB_HOME to an absolute location before the first launch to use a different root. CLI context and history use the platform state directory with owner-only permissions.

OPERATE

Security checklist

  • Keep development mode bound to 127.0.0.1.
  • Enable authentication and TLS before accepting network connections.
  • Give applications the smallest API-key role they need.
  • Store passwords and API keys outside source code and logs.
  • Restrict filesystem access to the PacificDB data and backup roots.
  • Verify backups and perform restoration drills on isolated data roots.
  • Review the repository security policy before deployment.

OPERATE

Troubleshooting

port 9000 is in use by a service that is not PacificDB

Another program owns the default port. Stop that program or start PacificDB on another port, for example pacificdb --port 9001. Beta.11 verifies the PacificDB protocol instead of exposing a raw JSON parser error.

The CLI asks for a login

The automatic loopback launcher has authentication disabled. A login prompt means the CLI connected to an engine configured with authentication. Use a valid account, or check the selected host and port with context show.

The npm CLI cannot start the engine

The npm package contains the client shell only. Install a native PacificDB package so db_engine is on PATH, start the engine separately, or connect with --host, --port, and --no-start.

select a database with: use <name>

Create or select a database before running collection, document, media, or vector commands. Run list databases and then use app.

A project cannot be selected

use project expects the canonical ID returned by create project or list projects, rather than the display name.

The engine is unavailable

Run status. Check engine.log under the platform home, confirm the host and port, and use pacificdb --no-start only when an engine is already running.

An installer is blocked by the operating system

Beta.11 Windows and macOS packages are unsigned. Confirm the installer checksum against the release manifest and follow your organization's policy for unsigned software. Signed packages are still pending.

Beta status and support

Beta.11 passed the retained Linux suite, real Debian package installation, cross-platform installer jobs, genuine disk-full scenarios, RF3 replication, network partition/election checks, and 64/128-client RF3 campaigns. It remains a beta rather than a universal production certification.

Open work includes physical power/storage-controller testing, mixed-version rolling upgrades, an independent security assessment, Windows signing, and macOS notarization.
